Course Objectives

實作核心目標：掌握人類的四大關鍵判斷

我們不只交代工作，更要成為嚴格把關成果的指揮者與審查員。

1

看懂它的計畫 (Plan Review)

動手前先檢查：讀哪裡、寫哪裡、是否有備份？嚴禁未經確認就隨意改寫或刪檔。

2

檢查它的成果 (Verification)

以 SHA-256 雜湊與極端條件測試成果，不依賴 AI 單方面的「已完成」宣告。

3

辨認需確認的動作 (Confirmation)

嚴格劃分權限邊界：只處理指定的單一題目資料夾，禁止連外或越權碰觸其他目錄。

4

退回不合理做法 (Rejection)

面對擅自刪檔、自補猜測數據、自動對外公開等具資安風險計畫，能精準退回並提具體修正規範。

Task A · 整理社團檔案

一張任務卡，整理一個混亂資料夾

Commit: 148d85f
1. 完整性檢驗

盤點 12 筆 input 檔案，原始檔案 100% 保持只讀不動。所有複製副本經 SHA-256 雜湊逐一比對完全吻合。

2. 拒絕「檔名定稿偏誤」

proposal_final.txt（戶外30分）與 proposal_final2.txt（室內20分）內容截然不同。堅持不因檔名刪除任何版本，全數保留供決策。

3. 結構化交付

分類為 proposals/、admin/、publicity/，產出 manifest.json（12 筆來源對照）與 report.md 整理報告。

💡 關鍵驗收原則：原檔不可動、重複檔各留副本、不同版本全保留、產出清單嚴格遵循 JSON 陣列規格。

Task B v2 · 需求迭代

「至少改一次」：鍵盤快捷鍵極速操作

Commit: 746fce3
原來的情況 (Before)

使用者每次想抽活動或重設條件時，都必須拿起滑鼠移動游標點選按鈕，在電腦大螢幕連續測試時操作流程略顯繁瑣。

提出的修改 (Request)

增加全局鍵盤快捷鍵：按 Space 或 Enter 觸發「幫我選」、按 R 重設篩選；按鈕增加快捷提示徽章並具防呆機制。

修改與重測 (After & Retest)

雙手無需離開鍵盤即可極速抽選與復原；下拉選單操作時不會誤觸；中英文切換時快捷文字同步支援。

性質判定： 新需求 (New Requirement) 非 AI 漏做原規格，而是為了提升終端體驗的主動改進。

Task D · 共同討論與安全防禦

這份計畫你會按同意嗎？堅決退回！

Commit: a5f25d8
❌ 模擬惡劣計畫：「我會把 Downloads 全部整理，刪除重複檔，把 final2 當最新版；找不到資料就補一個合理值，完成後自動公開成果。」
1. 拒絕越權擴大範圍
不可整理整台電腦 Downloads，僅限指定工作資料夾。
2. 拒絕不可逆刪檔
不可直接刪除重複檔，應在 output 留副本或列清單。
3. 拒絕草率認定定稿
不可將 final2 當最新版，必須完整保留所有版本。
4. 拒絕虛構猜測數據
找不到資料不可「補合理值」，需原樣標註異常。
🔒 退回守則：產出成果一律留存在本機，未經使用者人工複審，嚴禁任何自動連外與公開發布行為。
